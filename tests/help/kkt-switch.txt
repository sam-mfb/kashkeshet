Point this machine's clients at another kkt server, or with --local back at the one that runs here.

Checks the server first and changes nothing if it fails. Then points each client with kkt set up at it (backing up its config), and records it, so `kkt watch`, `register`, `reclaim` and `doctor` use it without --url and --key-file. A server that runs on this machine keeps running, and `kkt status` and `kkt upgrade` still manage it.

Usage: kkt switch [OPTIONS] [URL]

Arguments:
  [URL]
          The new server's MCP address, such as https://kkt.tail1234.ts.net/mcp

Options:
      --local
          Point the clients back at the server that runs on this machine

      --key-file <KEY_FILE>
          A file holding the new server's access key. Otherwise asked at a terminal, offering the current one; with no terminal, the current one

      --clients <CLIENTS>
          The clients to point at it, separated by commas (claude-code, codex, opencode, agy, muse-code), or `none`. Without it, every client with kkt set up now

  -h, --help
          Print help (see a summary with '-h')
