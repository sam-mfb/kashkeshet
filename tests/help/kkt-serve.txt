Run the server, with settings from a config file as well as flags.

Flags win over the file, and the file over the defaults. Without --db, the database is kashkeshet.db in the per-user data directory. Without --access-key-file, the key is ~/.config/kkt/access-key, created on first start; --no-access-key runs with none.

Usage: kkt serve [OPTIONS]

Options:
      --config <CONFIG>
          The config file. By default ~/.config/kkt/config.toml ($XDG_CONFIG_HOME/kkt/config.toml), if it exists

      --ignore-setup
          Start even though `kkt setup` set this machine up otherwise: as a Docker server, a client, or with the service running. The service passes it, since it is the server setup meant

      --db <DB>
          The SQLite database file. Created if missing [default: kashkeshet.db in the per-user data directory]

      --bind <BIND>
          Address to listen on. Must be a loopback address [default: 127.0.0.1:7420]

      --allow-any-bind
          Let --bind be a non-loopback address, such as 0.0.0.0 inside a container. Needs an access key

      --max-response-bytes <MAX_RESPONSE_BYTES>
          Largest response, in bytes, before it is cut short [default: 8192]

      --default-limit <DEFAULT_LIMIT>
          Items returned when an agent gives no `limit` [default: 20]

      --max-limit <MAX_LIMIT>
          Largest `limit` an agent may ask for [default: 100]

      --sends-per-minute <SENDS_PER_MINUTE>
          Messages one agent may send per minute [default: 30]

      --waiting-grace-seconds <WAITING_GRACE_SECONDS>
          Seconds completed waits remain listening [default: 3]

      --upgrade-backups-kept <UPGRADE_BACKUPS_KEPT>
          Backups the server keeps of those it makes before upgrading the database [default: 5]

      --max-lane-chars <MAX_LANE_CHARS>
          Longest lane instructions, in characters [default: 8000]

      --max-memory-entry-chars <MAX_MEMORY_ENTRY_CHARS>
          Longest memory entry an avatar keeps, in characters [default: 20000]

      --max-memory-chars <MAX_MEMORY_CHARS>
          Most characters in one avatar's memory, all entries together [default: 100000]

      --name-pack <NAME_PACK>
          Word pack for new avatars' handles [default: animals]

      --allow-origin <ALLOW_ORIGINS>
          A browser origin allowed to call /mcp, e.g. http://localhost:6274 for MCP Inspector. Repeat for more. By default no browser origin is allowed

      --allow-host <ALLOW_HOSTS>
          A host name the server answers to besides localhost, 127.0.0.1 and ::1, e.g. host.docker.internal or a Tailscale name. Add `:port` to allow only that port. Repeat, or separate names with commas, for more

      --instructions <INSTRUCTIONS>
          A file whose text is sent to every agent that connects, in place of the built-in instructions (agent-instructions.md)

      --access-key-file <ACCESS_KEY_FILE>
          A file holding the access key. Every /mcp request must send `Authorization: Bearer <key>`. The web page uses a separate web-key beside it [default: ~/.config/kkt/access-key, created if missing]

      --no-access-key
          Run with no access key: anyone who can reach the server can use it

      --log-file <LOG_FILE>
          Write the log to this file instead of stdout. It stays under about 60 MB: rolled over at 10 MB, five rolled files kept, none older than 30 days

      --log-level <LOG_LEVEL>
          How much kkt's own code logs: error, warn, info, debug or trace [default: info]

      --dependency-log-level <DEPENDENCY_LOG_LEVEL>
          How much the libraries kkt uses (the MCP library, the web server) log: error, warn or info. At info, the MCP library logs several lines for every request; debug and trace are refused, because there it logs request contents, tokens included [default: warn]

  -h, --help
          Print help (see a summary with '-h')
