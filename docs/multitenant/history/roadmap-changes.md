# Changes to roadmap.md from the 2026-11-01 review, points 3 to 18

Checked against `origin/next` at `b206f24`. Every code citation in the review held: `rules/messages.rs` authenticates once before waiting and ignores non-message notices; `web/real.rs::live` forwards the global subscription and `web/mod.rs::events` keeps no viewer; `events.rs` carries `AgentHidden.channels`, member counts and `Missed(n)`; `rules/human.rs::agent_view` bundles memory and `admin_agent` reuses it; `overview` bundles the server run; `app.rs::admit` drops the principal; `mcp_admin.rs::CreateChannelParams` has no swarm; `rules/rate.rs::SendLimiter` is per agent at 30/min and `RegisterLimiter` per server; `hide_agent` and `stale.rs` refuse or keep owners; `remove_avatar_in` posts in owned-but-left channels; `access::decide` needs member and owner together; `list_lanes` is token-free; `initialize` and `discover` return the announcement; `reclaim` returns announcement, lane and memory. Points 1 and 2 are untouched; section 13 says they are open.

- **3.** First server admin stays in the config file, named by issuer and subject, or by email only where a configured claim attests it verified (never on Entra). It is a bootstrap: consumed in the first matching sign-in, role bound to that subject, grants nothing after; racing first sign-ins yield one admin; restart does not regrant. Lockout recovery is a new bootstrap line, consumed once. Section 11's "matched to the email" is now the same bootstrap. Invitations require the attested verification too (8.4, 8.5).
- **4.** Every request matches an org-bearing claim to the stored org; a mismatch is refused and the user is not moved. Tokens without an org claim are accepted only for invited users. A removed user leaves a disabled row that refuses the same subject until re-added. Claim bindings are unique; a token matching a binding and an invitation in different orgs is refused. Tests in E.
- **5.** Claim binding and the server role are the server admin's only; org admins manage org roles, invitations, groups. Section 10's org admin page loses "login settings (claim binding)". Section 3 states every relationship is same-org and the store refuses writes that cross it; section 12's capability tests cover writes.
- **6.** 8.7 defines the page sign-in transaction: short-lived, single use, browser-bound cookie, state, nonce, PKCE, fixed callback, same-origin return path, id_token audience = page client ID, separate from access-token verification, `SameSite=Lax` transaction cookie with the `Strict` session cookie set via a same-origin landing. `TokenVerifier` returns resource, scopes, expiry, verified-email flag, org claim and human-versus-application grant; application-only tokens refused. Pinned algorithms, future `nbf`, missing claims and wrong token kinds refused; key refresh bounded. Negative tests in B.
- **7.** Section 4 "Live feeds": waits and feeds carry the subscriber and its credential deadline, end on deactivation, reclaim, sign-out, role or access loss, user removal and org suspension, wake and recheck. 8.7's revocation names the web session as kkt's own window that outlives the provider token. Revocation tests are in B, not D.
- **8.** Section 5 gets a concrete inventory: nested event fields, lag report with no count, member previews, waiting-channel lists, memory, aggregate counts, server settings, hidden and deactivated records. Avatar details split from memory; server-run details are a server-admin read. Event decisions stay in `rules`. Tests on complete serialized results with foreign markers, pagination and slow subscribers; "no third metadata exception" stated.
- **9.** Section 12 restructured: B carries request-scoped identity, role checks on every existing tool and page, bootstrap server-and-org admin, minimal user pages, revocation, HTTP tests with three roles; `login --user` moves to C, which gets owner-only tests; D is shared-swarm transitions only; E is multi-org admission only.

Redemption checks active user, org, swarm and current access in the transaction that spends a use and inserts; taken handle, bad lane or failed insert spends nothing; last-use and deactivation races defined. Codes from `Entropy`, at least 128 bits; failed guesses under the unauthenticated limit.
