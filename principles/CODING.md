# Coding Practices

1. When not inconsistent with the principles of this project, developers SHOULD follow standard and idiomatic conventions in the language and framework they are using.

2. When not inconsistent with the principles of this project or with rule 1, developers SHOULD make their code consistent with surrounding code.

3. When a language and its community are agnostic on the subject, developers SHOULD prefer a functional programming paradigm over an object-oriented one. E.g., use factory functions instead of class constructors.

4. Developers MUST write code that is readable. Developers SHOULD prefer readability to being concise or clever.

5. Developers SHOULD NOT abstract simply because code is duplicated once.

6. Developers SHOULD NOT optimize code before a need is apparent.

7. Documentation in code ("comments") SHOULD be used sparingly and MUST NOT simply describe what the code obviously does.

8. Code SHOULD NOT rely on implicit defaults. Every default MUST be defined explicitly.
